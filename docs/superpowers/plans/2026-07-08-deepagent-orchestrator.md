# Plan: LangChain DeepAgent Orchestrator

> **Goal:** Replace the current keyword-routing StateGraph with a `create_agent` ReAct agent that uses tools to delegate to subagents. The orchestrator becomes a single LangGraph agent with filesystem/memory tools + subagent delegation tools.

**Date:** 2026-07-08
**Status:** Final Plan

---

## Context

### Current State (what we have)

The orchestrator is a **custom StateGraph** (`src/agent/graph.py`) with hardcoded classify → route → execute_* → synthesize nodes. Each execute node makes a raw LLM call with a hardcoded system prompt — **no tools, no ReAct loop, no delegation**.

All tools use **OpenAI Agents SDK** `@function_tool` decorator (requires `RunContextWrapper`), which is incompatible with LangChain's `@tool`.

### Target State (what we're building)

A **LangChain ReAct agent** built with `create_agent()` (LangGraph v1 API) that:
- Has filesystem + memory + search tools for direct operations
- Has subagent delegation tools for complex tasks
- Uses ReAct loop to decide when to delegate vs. act directly
- Streams tool calls and responses to the CLI

### API Note

`create_react_agent` from `langgraph.prebuilt` is **deprecated** in LangGraph v1+ (installed: `langgraph 1.2.7`). Use `langchain.agents.create_agent` instead:

```python
from langchain.agents import create_agent

agent = create_agent(
    model="deepseek-v4-flash-free",
    tools=[...],
    system_prompt="You are the motor-deepagent orchestrator...",
)
```

## Architecture

```
User → CLI REPL → create_agent (ReAct loop)
                     │
                     ├── [Direct tools]
                     │   ├── read_file, write_file, list_directory, grep_files
                     │   ├── store_memory, search_memory
                     │   └── tavily_search
                     │
                     ├── [Subagent tools]
                     │   ├── delegate_coding   → RepoCodingAgent (create_agent)
                     │   ├── delegate_wiki     → WikiManager (create_agent)
                     │   ├── delegate_research → ResearchSubgraph (create_agent)
                     │   └── delegate_experiment → ExperimentRunner (create_agent)
                     │
                     └── [Structured output]
                         └── WikiUpdatePlan (generated by orchestrator, applied by WikiManager)
```

### Data Flow

1. **Simple tasks** → orchestrator uses direct tools (read a file, search memory)
2. **Complex tasks** → orchestrator calls subagent tool → subagent runs with its own tools → returns result string
3. **Wiki updates** → orchestrator generates `WikiUpdatePlan` via `generate_wiki_plan` tool → WikiManager tool applies it
4. **Mixed tasks** → orchestrator chains multiple tool calls in a single ReAct loop

## Task 1: LangChain Tool Wrappers

**File:** `src/agent/tools.py` (CREATE)

Convert existing OpenAI Agents SDK tools to LangChain `@tool` format. The underlying logic (path resolution, sandboxing, file I/O) is reused from `src/tools/filesys/backend.py` and `src/memory/long_term.py` — we just change the decorator and drop `RunContextWrapper`.

### Tools to implement:

**Filesystem** (reuse logic from `src/tools/filesys/file_tools.py`):
- `read_file(path, max_chars)` → reads a file
- `write_file(path, content)` → writes a file
- `grep_files(pattern, path, glob)` → searches files
- `list_directory(path, pattern, depth)` → lists files

**Memory** (reuse logic from `src/tools/memory/__init__.py`):
- `store_memory(namespace, content, key)` → stores a fact
- `search_memory(query, namespace)` → searches memory
- `list_memories(namespace)` → lists memory namespaces
- `forget_memory(key, namespace)` → deletes a memory

**Search** (reuse logic from `src/tools/search/tavily_search.py`):
- `web_search(query, max_results)` → Tavily web search

**Subagent delegation** (call compiled `create_agent` graphs):
- `delegate_coding(task)` → runs RepoCodingAgent
- `delegate_wiki(task)` → runs WikiManager
- `delegate_research(query)` → runs ResearchSubgraph
- `delegate_experiment(script_path, args)` → runs ExperimentRunner

**Wiki planning:**
- `generate_wiki_plan(findings, target_pages)` → returns `WikiUpdatePlan` JSON

### Implementation pattern:

```python
from langchain_core.tools import tool

@tool
def read_file(path: str, max_chars: int = 0) -> str:
    """Read a file. Accepts virtual paths (/workspace/...) and real paths."""
    from src.tools.filesys.backend import resolve
    from src.config import settings
    # ... reuse existing logic from file_tools.py (without RunContextWrapper)
```

For subagent tools, the pattern wraps a compiled agent:

```python
@tool
def delegate_coding(task: str) -> str:
    """Delegate code inspection, patching, or analysis to the RepoCodingAgent."""
    from src.agent.build_agent import get_coding_agent
    agent = get_coding_agent()
    result = agent.invoke({"messages": [{"role": "user", "content": task}]})
    return result["messages"][-1].content
```

## Task 2: Agent Builder

**File:** `src/agent/build_agent.py` (MODIFY)

Replace the `build_orchestrator()` dict-based config with actual `create_agent()` calls.

### Changes:

1. Remove `build_orchestrator()` (returns a dict — not used)
2. Add `build_orchestrator()` that returns a **compiled agent** using `create_agent()`
3. Add `get_coding_agent()`, `get_wiki_agent()`, `get_research_agent()`, `get_experiment_agent()` — each returns a compiled `create_agent()` instance

### Implementation:

```python
from langchain.agents import create_agent

def build_orchestrator(model: str | None = None):
    """Build the orchestrator as a ReAct agent with all tools."""
    from src.agent.tools import ALL_TOOLS
    from src.agent.prompts import ORCHESTRATOR_SYSTEM

    return create_agent(
        model=model or settings.MODEL_DEFAULT,
        tools=ALL_TOOLS,
        system_prompt=ORCHESTRATOR_SYSTEM,
    )

def get_coding_agent(model: str | None = None):
    """Build the RepoCodingAgent as a standalone ReAct agent."""
    from src.tools.filesys import read_file, write_file, grep_files, list_directory
    from src.tools.memory import store_memory, search_memory

    return create_agent(
        model=model or settings.MODEL_DEFAULT,
        tools=[read_file, write_file, grep_files, list_directory,
               store_memory, search_memory],
        system_prompt=REPO_CODING_SYSTEM,
    )
# ... similar for wiki, research, experiment agents
```

### Subagent tools accept task descriptions and return result strings:

Each subagent tool wraps a compiled `create_agent` and invokes it synchronously (blocking the orchestrator's ReAct loop until the subagent finishes). The result is the subagent's final AI message content.

    """Handle free-form chat input through the ReAct agent."""

    handler = StreamHandler(ctx.renderer)
    synthesis = await handler.handle_stream(

## Task 5: Runtime Integration

**File:** `src/agent/runtime.py` (MODIFY)

Add the new agent-based functions alongside the existing graph functions.

### New functions:

```python
async def run_agent_streamed(
    request: str,
    agent=None,
    thread_id: str = "default",
) -> AsyncIterator[dict[str, Any]]:
    """Process a request through the ReAct agent with streaming."""
    if agent is None:
        agent = build_orchestrator()

    config = {"configurable": {"thread_id": thread_id}}

    async for event in agent.astream_events(
        {"messages": [{"role": "user", "content": request}]},
        config=config,
        version="v3",
    ):
        kind = event["event"]

        if kind == "on_chat_model_stream":
            chunk = event["data"]["chunk"]
            if chunk.content:
                yield {"type": "token", "data": chunk.content}

        elif kind == "on_tool_start":
            yield {
                "type": "tool_start",
                "tool": event["name"],
                "input": event["data"].get("input", ""),
            }

        elif kind == "on_tool_end":
            yield {
                "type": "tool_end",
                "tool": event["name"],
                "output": str(event["data"].get("output", ""))[:500],
            }

        elif kind == "on_chain_end" and event["name"] == "Agent":
            # Final response
            output = event["data"].get("output", {})
            messages = output.get("messages", [])
            if messages:
                last = messages[-1]
                content = last.content if hasattr(last, "content") else str(last)
                yield {"type": "synthesis", "data": content}
```

Keep existing `run_request_graph()` and `run_request_graph_streamed()` for backward compatibility — they still work and can be used as fallback.

## Task 6: WikiUpdatePlan Handling

**Decision:** The orchestrator generates the plan, the Wiki Manager applies it.

### Flow:

1. Orchestrator calls `generate_wiki_plan(findings="...", target_pages=["motorcad/workflow.md"])`
2. Tool returns a `WikiUpdatePlan` as JSON string
3. Orchestrator calls `delegate_wiki(task="Apply this update plan: {plan_json}")`
4. Wiki Manager (with its own filesystem tools) reads existing pages, applies changes, reports back

### Why not have the orchestrator apply it directly?

The Wiki Manager has its own context window with wiki-specific instructions. It can:
- Check for duplicate sections
- Merge content cleanly
- Preserve existing structure
- Flag conflicts

This separation of concerns keeps the orchestrator focused on orchestration.

## Task 7: Streaming Handler Update

**File:** `apps/cli/streaming.py` (MODIFY)

Handle the new event types from `agent.astream_events()`:

```python
async def handle_stream(self, stream) -> str:
    synthesis = ""
    async for event in stream:
        etype = event.get("type", "")

        if etype == "token":
            self.renderer.stream_token(event["data"])  # Live token streaming

        elif etype == "tool_start":
            self.renderer.panel_tool_start(event["tool"], event["input"])

        elif etype == "tool_end":
            self.renderer.panel_tool_end(event["tool"], event["output"])

        elif etype == "synthesis":
            synthesis = event.get("data", "")
            self.renderer.panel_synthesis(synthesis)

        elif etype == "category":
            self.renderer.panel_classify(event["data"])

    return synthesis
```

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| `create_agent` not in installed langchain | High | Check `pip show langchain` first; fall back to `create_react_agent` from `langgraph.prebuilt` if needed |
| Subagent tools block orchestrator | Medium | Acceptable for now; async subagent tools can be added later |
| OpenAI-compatible endpoint doesn't support tool calling | High | Opencode endpoint must support function calling; test with simple tool first |
| Token overhead from tool descriptions | Low | Keep tool descriptions concise; use `tool减速` (short descriptions) |
| Streaming performance with many tool calls | Low | Buffer tool outputs; show summary not full output |
